# 内存振偏移查找与更新经验

## 0. 文档目的

本文档用于在游戏版本更新后，重新定位、只读验证并更新以下项目中的内存振相关偏移：

```text
J:\Code\C++\dma\er_new\YJWJ_DMA_NEW\Naraka\Hook.cpp
J:\Code\C++\dma\er_new\YJWJ_DMA_NEW\Naraka\Offset.h
```

目标是让没有历史上下文的开发者或 AI 能够直接执行更新，并且能明确区分：

1. `GameAssembly.dll`、`GameAssembly_Super.dll`、`GameAssembly_Super_IBT.dll` 的模块 RVA。
2. dump 可直接确认的 managed field offset。
3. 必须通过 DMA runtime object / MethodInfo / vtable 验证的值。
4. shellcode 自身布局常量与游戏版本偏移。

本文档记录的是查找方法和当前代码映射，不表示所有当前数值都已在本次会话重新做过运行时验证。

## 2. 当前入口与分支

`Hook::InitMemoryShockHook()` 当前按模块变体选路：

```text
Offset::IsGameAssemblyDefault() == true
    -> Hook::VirtualShockHOOK()

Super / SuperIBT
    -> Hook::KnifeStartHook_CrossFade()
```

因此版本更新时至少要分别审计 Normal 的 Virtual 路径和 Super 的 CrossFade 路径。`Hook::KnifeStartHook()` 是 Legacy 路径；`Hook::InitFlushStateHook()` 是旧动画加速实验路径，当前不是 `InitMemoryShockHook()` 主分支，但其版本相关字段也已集中到 `Offset.h`。

## 4. 成功查找流程

### 4.1 先确认实际模块变体

必须枚举目标进程模块，并按实际名称选择：

```text
GameAssembly.dll
GameAssembly_Super.dll
GameAssembly_Super_IBT.dll
```

不要依据登录界面、模式名称或上一次运行推断。所有 RVA 都只能与其对应模块基址相加。

记录：

```text
pid=
moduleName=
moduleBase=
moduleSize=
```

### 4.2 从 dump 提取 managed 字段与方法 RVA

搜索命令示例：

```powershell
rg -n -C 8 "class TransparentTagHandler|class CharacterManager|class EntityKit|class ActorModel|class ActionBreakData|class AnimPlayable|CrossFadeInFixedTime|CacheDelayBreakType|actorKitInteractableDevice|AnimPlayableAgent|mainPlayerActorModel|refCharacterMgr" "J:\Code\C++\dma\er_new\dump\dump2026.09.03\dump2026.09.03.cs"
```

方法 RVA 是方法声明上方的 `// RVA:`，不是方法声明下方下一项的 RVA，也不是固定 `VA`。

当前 `2026.09.03` Normal dump 明确给出：

### 4.3 查找并验证 TTH TypeInfo RVA

Normal 使用：

```text
C:\Users\JackLong\.codex\skills\dma-normal-offset-finder\SKILL.md
```

Super / SuperIBT 使用：

```text
C:\Users\JackLong\.codex\skills\dma-super-offset-finder\SKILL.md
```

最终候选必须通过以下只读校验：

```cpp
klass = ReadPtr(GameAssemblyBase + tthRva);
name  = ReadCString(ReadPtr(klass + Offset::Il2CppClassNameOffset));
// name 必须精确为 "TransparentTagHandler"

staticFields = ReadPtr(klass + Offset::Il2CppClassStaticFieldsOffset);
instance     = ReadPtr(staticFields + Offset::Il2CppStaticInstanceOffset);
instanceKlass = ReadPtr(instance);
// instanceKlass 应等于 klass
```

登录界面中 `instance`、`actorKit`、`refCharacterMgr` 可能尚未初始化。此时 TypeInfo 名称验证成功但实例链为空，不应把 RVA 判为错误；进入对局后再次验证对象链。

### 4.4 验证 CrossFade 主对象链

当前 Super/CrossFade vtable 链等价于：

```cpp
tthClass      = ReadPtr(GameAssemblyBase + Offset::InitActorKitRefer);
tthStatic     = ReadPtr(tthClass + Offset::Il2CppClassStaticFieldsOffset);
tthInstance   = ReadPtr(tthStatic + Offset::Il2CppStaticInstanceOffset);
localActorKit = ReadPtr(tthInstance + Offset::MemoryShockTransparentTagHandlerActorKitOffset);
interactable  = ReadPtr(localActorKit + Offset::ActorModel.ActorKitS.InteractableDevice);
vtableBase    = ReadPtr(interactable + 0x0);
slotAddress   = vtableBase + Offset::MemoryShockInteractableVtableSlotOffset;
originalTarget = ReadPtr(slotAddress);
```

通过条件：

1. 每一级都是 canonical user pointer。
2. `ReadPtr(tthInstance) == tthClass`。
3. `originalTarget` 位于当前 GameAssembly 模块 `[base, base + size)`。
4. `originalTarget - base` 是稳定 RVA；重启游戏后 VA 可变，RVA 应保持一致。
5. 在只读 probe 中同时打印 `slotAddress/originalTarget/originalRva`。

历史成功现场曾得到 `originalTarget RVA=0xCBA5500`，旧分支目标位于 `0xCBA55A8/0xCBA5630/0xCBA5669`。这些只可作为旧版本控制流锚点，不能直接复制到新版本。

### 4.5 验证本地玩家身份链

CrossFade shellcode 当前用两边 ActorModel 指针相等来限制“只处理自己”：

```cpp
hookActorModel = ReadPtr(ReadPtr(hookContext +
    Offset::MemoryShockHookContextEntityKitOffset) +
    Offset::MemoryShockEntityKitActorModelOffset);

tthClass    = ReadPtr(GameAssemblyBase + Offset::InitActorKitRefer);
tthStatic   = ReadPtr(tthClass + Offset::Il2CppClassStaticFieldsOffset);
tthInstance = ReadPtr(tthStatic + Offset::Il2CppStaticInstanceOffset);
manager     = ReadPtr(tthInstance + Offset::MemoryShockTransparentTagHandlerCharacterManagerOffset);
localActor  = ReadPtr(manager + Offset::MemoryShockCharacterManagerMainPlayerOffset);

self = hookActorModel == localActor;
```

只读 probe 至少要在自己和附近其他 Actor 都会经过入口的场景记录两组样本，证明比较能区分对象。只看到一次相等不能证明过滤正确。

### 4.6 通过 MethodInfo runtime resolver 查方法

`Hook.cpp` 已有 `ResolveAnimPlayableMethod("CrossFadeInFixedTime", 7)`。推荐顺序：

1. 从本地 `ActorModel` 读取 `ActorKit`。
2. 从 `ActorKit + AnimPlayableAgent` 读取 `AnimPlayable` object。
3. 读取 object 的 klass。
4. 遍历 klass 及 parent chain。
5. 在 `klass->methods` 中匹配方法名和参数数量。
6. 读取 `MethodInfo.methodPointer`。
7. 确认方法地址位于当前 GameAssembly 模块内。
8. 输出 `MethodInfo/VA/RVA/params/slot`。

对应 runtime layout 变量：

```text
Offset::Il2CppClassNameOffset
Offset::Il2CppClassParentOffset
Offset::Il2CppClassMethodsOffset
Offset::Il2CppClassMethodCountOffset
Offset::Il2CppMethodPointerOffset
Offset::Il2CppMethodNameOffset
Offset::Il2CppMethodSlotOffset
Offset::Il2CppMethodParameterCountOffset
```

只有 resolver 失败时才允许使用 `AnimPlayableCrossFadeInFixedTimeNormal/Super` 回退 RVA。

### 4.7 Legacy / Virtual 裸函数 RVA 的更新方法

`MemoryShockLegacy*Rva` 和 `MemoryShockVirtualCall*Rva` 没有可靠 managed 名称时，按以下流程更新：

1. 从已验证 vtable slot 取得当前 `originalTarget`。
2. DMA 只读导出入口前后至少 `0x300` 字节。
3. 用 x64 disassembler 解析基本块，不要手工按字节猜指令边界。
4. 对照旧实现的控制流特征：条件分支、间接跳转、调用数量、参数寄存器和返回块。
5. 将每个旧 `CALL/JMP` 映射到新基本块，并记录映射依据。
6. 对候选目标读取入口字节，确认位于模块可执行范围且不是全零/数据区。
7. 做只读日志验证后再更新 `Offset.h`。

不能使用“新 RVA = 旧 RVA + 模块整体差值”。IL2CPP codegen 的函数和基本块会独立重排。

## 5. 每次版本更新的执行顺序

1. 备份 `Offset.h` 当前值并记录 commit/hash。
2. 枚举实际加载模块，确定 Normal、Super 或 SuperIBT。
3. 使用对应 skill 更新 `m_TransparentTagHandler`，并验证 klass 名称。
4. 从最新 dump 更新 `ActorKit/EntityKit/TTH/CharacterManager/ActionBreakData` 字段。
5. 运行只读对象链，确认 local actor、actor kit、interactable、vtable slot。
6. 运行 MethodInfo resolver，获取 `AnimPlayable.CrossFadeInFixedTime` runtime RVA。
7. 更新对应 Normal/Super fallback，不要覆盖另一变体。
8. 只读反汇编并更新 Legacy/Virtual 的 CALL/JMP RVA。
9. 搜索 `Hook.cpp` 中是否又出现裸模块 RVA。
10. 编译并进行初始化、开关、恢复验证。

裸模块 RVA 审计命令：

```powershell
rg -n "Offset::(?:GameAssembly|NarakaBladepoint) \+ 0x[0-9A-Fa-f]+" "J:\Code\C++\dma\er_new\YJWJ_DMA_NEW\Naraka\Hook.cpp"
```

预期无输出。shellcode 中的 managed field displacement 也应由 `Offset.h` 生成，不应再次手写 `0x70/0xD8/0x58/0x198`。

## 6. 写入前后的验证门槛

### 6.1 只读阶段

必须先满足：

```text
module variant 已确认
TTH klass name == TransparentTagHandler
TTH instance klass == TTH klass
localActorModel / actorKit / breakData 可读
vtable slot target 位于当前 GameAssembly
CrossFade MethodInfo name/params/VA/RVA 全部一致
入口字节非零且符合预期函数 prologue
```

### 6.2 初始化阶段

写 shellcode 后、patch vtable 前必须 readback 整块并逐字节比较。失败时不允许继续 patch。

日志至少包含：

```text
[MemoryShock] module=<name> base=0x... size=0x...
[MemoryShock] TTH_RVA=0x... class=0x... instance=0x...
[MemoryShock] actorKit=0x... interactable=0x...
[MemoryShock] slot=0x... original=0x... originalRVA=0x...
[MemoryShock] CrossFade MethodInfo=0x... RVA=0x... params=7
[MemoryShock] shell=0x... size=... write=1 match=1
```

### 6.3 ON/OFF/restore 阶段

检查：

```text
ON:      ReadPtr(slot) == shellcode
OFF:     control byte == 0，或当前实现定义的关闭状态
restore: ReadPtr(slot) == originalTarget
```

退出辅助但不退出游戏后再次启动，还要验证 metadata reuse 路径能识别旧 shellcode，并恢复真实 `originalTarget`，不能把旧 shellcode 当原函数。

## 7. 当前已知风险与不一致

1. `J:\Code\C++\dma\er_new\dump\dump2026.09.03\dump2026.09.03.cs` 给出的 Normal `AnimPlayable.CrossFadeInFixedTime` 是 `0x5975FF0`，而代码回退值 `Offset::AnimPlayableCrossFadeInFixedTimeNormal` 仍为 `0x5811350`。后者对应 2026-08-13 dump。当前必须依赖 runtime resolver；在未做当前 Normal DMA 验证前不要直接改写并宣称已验证。
2. `Offset::AnimPlayableCrossFadeInFixedTimeSuper=0x797D760` 来自历史 runtime MethodInfo 验证，本次没有对当前进程重新验证。
3. `Offset::MemoryShockFlushAnimPlayableOffset=0x2C0` 是旧 FlushState 路径观察值；当前 dump 的 `ActorKit.AnimPlayableAgent` 是 `0x2E8`。两者上下文不同，不能自动合并。
4. `Offset::MemoryShockVirtualBreakCacheOffset=0x10` 与当前 dump 的 `ActionBreakData.CacheDelayBreakType=0x58` 不一致。Virtual 旧 shellcode 的字段语义尚未确认，不能直接用 `0x58` 替换。
5. Legacy 与 Virtual 的 CALL/JMP RVA 当前只有历史来源，均应标记为待当前版本反汇编验证。
6. shellcode 中部分字段使用 x64 `disp8` 编码。代码已用 `static_assert(offset <= 0x7F)` 防止字段增长后静默截断；若未来字段大于 `0x7F`，必须改成 `disp32` 指令编码并同步 shellcode size/跳转位移。

## 8. 不属于游戏偏移的常量

以下值应继续留在 `Hook.cpp`，不要放进 `Offset.h`：

```text
shellcode size 与 metadata size
metadata magic / marker magic
codecave block 内 control、shellcode、metadata 的相对布局
RIP-relative displacement
stolen instruction size
debug structure字段偏移
CrossFade 参数值，例如 fixedTime、speed、sourceType、forceSyncLoad
shellcode 内部基本块跳转距离
```

例如 `kCrossFadeControlGateBytes` 中的 `A2 FF FF FF` 是当前 shellcode 布局计算出的 RIP-relative displacement，不是 GameAssembly RVA。

历史还提供：

```cpp
OffsetToBytesBE(Offset::GameAssembly + 0x80DFC40, CrossFadeInFixedTime);
```

它是当时 Super 的 `AnimPlayable.CrossFadeInFixedTime` 方法地址。后续版本已变化，当前必须按 MethodInfo runtime resolver 重新获取。

最可靠的成功经验不是记住某个 RVA，而是保留以下证据链：

```text
模块变体 -> TypeInfo klass 名称 -> runtime instance -> 本地 ActorKit
-> interactable vtable slot -> original target in module
-> AnimPlayable object klass -> MethodInfo name + params -> methodPointer RVA
```

只要这条证据链完整，版本更新就能明确知道是哪一级发生变化，而不是在所有常量中盲目试值。
