# 本机内存直读能力盘点（非 DMA）

> 结论先行：**存在**。项目里有两套与 DMA 完全解耦的本机读取路径——
> ① 跨进程直读（`ReadProcessMemory` / WinAPI 后端，已成体系，GUI 可直接切换）；
> ② 进程内自读（注入 DLL 后用裸指针 + SEH 直读宿主进程内存）。
> DMA / MemProcFS 只是可切换的第三条通道，并非唯一通道。

- 适用范围：同机、同会话（或具备 `SeDebugPrivilege`）的目标 Unity 进程
- 不适用：跨机、物理内存采样、被分页/受保护页的稳定取值（那属于 DMA 通道）
- 排查对象：`F:\gua\UnityExplorer-main`（本文所有路径均相对仓库根）
- 关键结论速查：`grep -rn "ReadProcessMemory" include App tests` 即可定位全部本机读点

## 1. 架构总览

```
                     ┌──────────────────────────────────────────┐
                     │   算法层（与通道无关）                     │
                     │   GOM / MSID / Transform / Camera / W2S   │
                     │   Metadata / DumpSDK2                     │
                     └───────────────────┬──────────────────────┘
                                         │ er2::IMemoryAccessor&
                    ┌────────────────────┴────────────────────┐
                    │                                          │
        ┌───────────▼────────────┐              ┌──────────────▼─────────────┐
        │ 本机通道 A：跨进程直读   │              │ 通道 C：DMA（另一条）        │
        │ WinApiMemoryAccessor   │              │ DMAMemoryAccessor          │
        │ ReadProcessMemory      │              │ VMMDLL_MemReadEx / Scatter │
        │ 需要 OpenProcess 句柄   │              │ 需要 vmm.dll / leechcore    │
        └───────────┬────────────┘              └────────────────────────────┘
                    │
        ┌───────────▼────────────┐
        │ 本机通道 B：进程内自读   │
        │ 注入 DLL 后裸指针解引用  │
        │ GetModuleHandleA + __try │
        └────────────────────────┘
```

三条通道共用 `er2::IMemoryAccessor` 接口，算法层无需任何改动即可互换。

## 4. 明确**不属于**本机通道的部分（避免误判）

| 位置 | 真实通道 | 证据 |
|---|---|---|
| `App\UnityExplorerMcpServer` | 控制面是本机 HTTP，**内存面只有 DMA** | `main.cpp:1183` `bindAddress = "127.0.0.1"`；`main.cpp:1048` `mode` 枚举仅 `{"dma"}`；依赖 `vmm.lib;leechcore.lib`，运行时需 `vmm.dll/leechcore.dll` |
| `App\ExternalResolveConsole` | CLI 只支持 DMA | `main.cpp:3811` `"only --mode dma is supported in headless mode"`（`--mode <dma>` 见 327 行） |
| `include\er2\unity2\headless\probe_cli.hpp` | 默认 `runMode = "dma"`（23 行） | 246 行解析 `--mode`，无 `winapi` 分支 |
| `deps\Memory\*`、`deps\DMALibrary\*`、`deps\Naraka\Memory\*` | 纯 DMA | 全部 `VMMDLL_MemReadEx` / `VMMDLL_MemWrite` / `Scatter` |
| `include\er2\os\dma\dma_memory_accessor.hpp` | 纯 DMA | `VMM_HANDLE` 驱动 |

另外，全库检索确认：**没有**驱动设备名 `\\.\Xxx` + `DeviceIoControl`、命名管道、共享内存式的
内存传输实现（`grep` 对 `DeviceIoControl|IOCTL|CreateNamedPipe|OpenFileMapping|Mailslot|WM_COPYDATA`
无命中）。因此本机直读的抽象层级**只有 WinAPI 一种**，不存在隐藏的驱动兜底。

## 5. 最小可用模板

### 5.1 同机跨进程直读（不加载任何 DMA 运行时）

```cpp
// LocalRead.cpp : 本机跨进程直读（WinAPI 后端，不初始化 DMA / vmm.dll）
#include "Resolve202x.hpp"
#include "er2/os/win/win_memory_accessor.hpp"
#include "er2/os/win/win_process.hpp"
#include <Windows.h>
#include <cstdio>
#include <cstdlib>

int main(int argc, char** argv) {
    const DWORD pid = (argc > 1)
        ? static_cast<DWORD>(std::strtoul(argv[1], nullptr, 10)) : 0;

    HANDLE h = er2::OpenProcessForRead(pid);   // PROCESS_QUERY_INFORMATION | PROCESS_VM_READ
    if (!h) {
        std::printf("[!] OpenProcessForRead failed: %lu\n", GetLastError());
        return 1;
    }

    er2::WinApiMemoryAccessor mem(h);          // ReadProcessMemory 封装

    er2::ModuleInfo up{};
    if (er2::GetRemoteModuleInfo(pid, L"UnityPlayer.dll", up))   // Toolhelp32 本机模块枚举
        std::printf("UnityPlayer.dll base=0x%llX size=0x%X\n",
                    static_cast<unsigned long long>(up.base), up.size);

    std::uintptr_t v = 0;
    if (mem.Read(up.base, &v, sizeof(v)))                        // 任意地址直读
        std::printf("first qword @base = 0x%llX\n",
                    static_cast<unsigned long long>(v));

    CloseHandle(h);
    return 0;
}
```

### 5.2 用 AutoInit 走完整算法层（同机）

```cpp
#include "Resolve202x.hpp"
#include <cstdio>

int main() {
    er2::SetContextBackend(er2::CreateDefaultContextBackend());  // 显式声明本机后端
    if (!er2::AutoInit()) return 1;                              // 自动找 Unity 进程

    std::printf("pid=%u runtime=%s gom=0x%llX msid=0x%llX\n",
                er2::Pid(), er2::ToString(er2::Runtime()),
                static_cast<unsigned long long>(er2::GomGlobalSlotVa()),
                static_cast<unsigned long long>(er2::MsIdToPointerSlotVa()));

    for (const auto& go : er2::FindObjectsOfTypeAll("GameObject")) {
        std::string name;
        if (er2::GetGameObjectName(go.native, name))
            std::printf("0x%llX %s\n",
                        static_cast<unsigned long long>(go.native), name.c_str());
    }
    return 0;
}
```

编译：MSVC / VS2022，C++17，x64，`/MT`，include 路径指向仓库根 + `include`，另需 GLM。

## 6. 使用约束与排障

| 现象 | 原因 | 处置 |
|---|---|---|
| `OpenProcessForRead failed: 5`（ERROR_ACCESS_DENIED） | 目标为受保护 / 反作弊进程；或权限不足 | 以管理员运行；确认同机同会话；高保护目标改用 DMA 通道 |
| `CreateToolhelp32Snapshot(TH32CS_SNAPMODULE)` 返回 `INVALID_HANDLE_VALUE` | 同上，属于本机通道的固有限制 | 见 `dump_workspace\research\hero-catalog\README.md` 记录的同一现象（错误 5） |
| 某些页读数全 0 或失败 | 页已分页 / 受保护 / `PAGE_GUARD` | 本机通道读不到；DMA 通道在此类页面更稳 |
| 想同时对比两条通道 | 两条通道共用 `IMemoryAccessor` | GUI 内切换 WinAPI/DMA 复跑同一扫描即可；`docs\superpowers\plans\2026-05-01-dma-unity-browser-layout-plan.md` 明确将 WinAPI 保留为同机调试与解析器行为对照 |
| 不想改代码验证 | 现成二进制 | `bin\Release`（GUI 走 WinAPI 单选）；`tests\winapi_smoke\Er2WinApiSmoke.vcxproj` 做回归 |

## 8. 一句话结论

本机直读**已具备且是默认路径**：算法层通过 `IMemoryAccessor` 解耦，`WinApiMemoryAccessor`
（`ReadProcessMemory`）提供跨进程直读，`AutoInit` 负责同机进程/模块发现，GUI 默认选中
`WinAPI` 单选即可用；注入侧另有一套进程内自读 DLL。DMA 是并列的第二通道，仅在受保护页、
高保护进程或跨机场景下才是必需项。
