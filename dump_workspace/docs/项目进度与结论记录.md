## 4. Unity-Offset.dll 逆向结论（重要）

### 4.1 源头源码已找到（最大捷径）
Unity-Offset.dll 基于开源项目 **[shalzuth/Il2CppRuntimeDumper](https://github.com/shalzuth/Il2CppRuntimeDumper)**
（证据：DLL 内嵌源码路径 `H:\C++Code\il2CppRuntimeDumperEx\...\il2cpp_dump.cpp`）。

源码已克隆：`dump_workspace/Il2CppRuntimeDumper_src/`（`Il2Cpp.cs` 43KB 核心 +
`Il2CppClass.cs`/`Il2CppMethod.cs`/`Il2CppField.cs`/`Dumper.cs`/`Program.cs`）。

### 4.2 完整机制（源码级确认）
1. **注入**：`NativeNetSharp.Inject` 自注入器；`JmpPatch`（12 字节
   `mov r11,target; jmp r11` inline hook + VirtualProtect + FlushInstructionCache）
2. **枚举程序集**：`il2cpp_domain_get` → `il2cpp_domain_get_assemblies` →
   `assembly_get_image` → `image_get_name`；反射 `il2cpp_runtime_invoke(GetAssemblies)`
3. **枚举类**：`il2cpp_image_get_class` / `il2cpp_image_get_class_count`
4. **类解析**：`class_get_name/namespace/flags/image/type/declaring_type/parent`
   + 缓存递归（CachedClasses + ClassesToAdd 队列）
5. **字段**：`class_get_fields` → `field_get_name/type/offset/flags`
6. **方法**：`class_get_methods` → `method_get_name/return_type/param_count/param/param_name`
7. **属性**：`class_get_properties` → `property_get_name/get_method/set_method`
8. **输出**：Mono.Cecil 重建 `DummyDlls\*.dll`（字段带 FieldOffset 属性）

### 4.3 为什么只能 dump 普通变体
- `UnityDllName = "GameAssembly"` 常量 + `GetModuleHandleA("GameAssembly.dll")` 精确匹配
- Super 变体 il2cpp_* 导出被 VMProtect 移除 → `GetProcAddress` 失败

### 4.4 对自研实现的指导
自研 `Il2CppRuntimeDumper` 机制与源码 **100% 对齐**（同一 API 集、同一遍历顺序、
同样字段偏移/方法参数/属性数据）。差异仅输出格式：它重建假 DLL，自研输出纯文本
dump.cs（字段偏移 `// 0x{offset}`、方法 RVA/VA 更明确）。
详细对照表见 `dump_workspace/docs/Unity-Offset逆向报告.md`。

## 5. DMA 注入（--dma-inject）现状

### 5.1 原理
复刻 PCILeech UMD 技术：DMA 写 shellcode + 劫持 IAT thunk / inline hook 函数头，
让游戏线程替我们执行 LoadLibraryA(dll) → 加载注入式 dump DLL。免句柄、免远程线程。

### 5.2 已验证可行的部分
- ✅ DMA 写能力：`VMMDLL_MemWrite` 全部返回成功（FPGA 固件支持写）
- ✅ 代码洞/数据洞定位：改用 `ReadModuleSections` 手工解析 PE 节表
  （`VMMDLL_ProcessGetSectionsU` 被反作弊破坏）
- ✅ LoadLibraryA 地址解析：`VMMDLL_ProcessGetProcAddressU` 正常
- ✅ inline hook 写入/恢复链路跑通（`restored=true`）
- ✅ 实测：GameAssembly 内代码洞 `0x7FF8BF431FE0`、数据洞 `0x7FF8CDC8CF63`

### 5.3 当前卡点
1. **IAT thunk 查找失败**：`VMMDLL_WinGetThunkInfoIATU` 全模块失败
   → NEAC 反作弊隐藏/篡改 PEB/IAT（Toolhelp 看不到进程佐证）
2. **shellcode 未执行**：hook `Animator.SetFloat`（VA 0x7FF8C355C9C0）后
   `executed=false` —— 该函数可能未被调用，或 inline shellcode 恢复逻辑待验证
3. **进程保护**：普通进程枚举（Toolhelp/Get-Process）看不到游戏进程，
   仅 DMA（FixCr3 后）可访问

### 5.4 已突破（2026-09-08 更新）
1. ✅ **hook 点选择修复**：改用 `VMMDLL_ProcessGetProcAddressU` 解析
   `kernel32!Sleep` 实际地址做 inline hook（不依赖被反作弊破坏的 IAT 查找）
2. ✅ **shellcode 修复**：
   - 数据地址改用 **rbx（非易失寄存器）**，修复 LoadLibraryA 调用后
     rax 被覆盖导致 status 写错地址的崩溃 bug
   - 布局统一：+0x20=status，+0x28=testOnly，+0x30=orig bytes，+0x40=dll path
   - LoadLibraryA 返回值存入 status 字段（可读 HMODULE 判断加载成功）
3. ✅ **test-only 模式**（`--dma-inject-test`）验证：**executed=true**！
   - 游戏线程实际执行了 shellcode（status 被置 1）
   - inline hook + DMA 写 + 执行 + 恢复整条链路 **100% 工作**
   - 游戏在 test-only 下存活（无崩溃）
4. ✅ **完整 LoadLibraryA 注入**：executed=true，LoadLibraryA 返回过有效
   HMODULE（0x18814）→ **DLL 曾成功加载进游戏进程**
5. ⚠️ **反复崩溃的根因（重要发现）**：
   - 代码洞/数据洞选在 **GameAssembly 的 .text/.data 节尾空洞**
   - GameAssembly 有 **VMP 保护（.vmp0/.vmp1）**，节尾空洞实际可能被
     VMP/运行时分配器占用 → 写入后与游戏自身数据冲突 → 崩溃
   - 且每次注入后 status 字段值不稳定（0x18814 / 0x3A00002000005D00）
     → 数据洞确实被游戏覆盖了
   - **结论**：DMA inline hook 注入对抗反作弊环境的稳定性受限于
     "代码洞/数据洞必须选在真正未用的内存"，这在 VMP 保护模块上难以保证

### 5.5 DMA 注入最终结论（2026-09-08）
- **技术原理已验证成功**：DMA 写 shellcode + inline hook + 游戏线程执行 +
  LoadLibraryA 调用 + hook 恢复，全链路跑通（executed=true 多次实测）
- **工程上不稳定**：GameAssembly（VMP）节尾空洞不可靠，写入后游戏崩溃
- **可靠路径**：CE 注入（用户已有，Unity-Offset.dll 同款方式）验证自研
  DLL 的 dump 能力——游戏下载完成后执行
- **改进方向**（若继续攻坚 DMA 注入）：
  1. 代码洞改到主模块（NarakaBladepoint.exe，无 VMP）——但其节表被
     NEAC 隐藏，需手工解析 PE（DMA 直读文件头可行）
  2. 或使用 VirtualAlloc 等效（DMA 无法调用，需先注入 shellcode 自申请）
  3. 或接受"DMA 注入原理可行但本环境不稳定"，用 CE 注入兜底

### 5.4 下一步（DMA 注入攻坚方向）
1. **hook 高频函数**：用 `VMMDLL_ProcessGetProcAddressU` 解析 `kernel32!Sleep`
   实际地址做 inline hook（Sleep 几乎必然被调用）——dma_inject 已支持
   hookFunction 传函数名自动解析
2. **验证 inline shellcode 恢复**：对齐源码 `JmpPatch` 逻辑（保存原字节→覆盖→跳转）
3. **CE 注入优先**：反作弊环境下 CE 注入（用户已有）比 DMA 注入更可靠，
   DMA 注入作为免句柄的进阶方案持续攻坚

## 11. 299KB Unity-Offset.dll 逆向定论：导出解析机制（2026-09-08）

> 对 `F:\gua\dump\Unity-Offset.dll`（299KB，普通体可正常 dump 的版本）做了完整
> dumpbin 反汇编（.text 位于 VA 0x180001000，196KB 代码）+ 字符串定位分析，
> **彻底确认它的导出解析机制就是普通的 GetProcAddress**——与我们自研 dumper 同机
> 制。其能成功而自研 DLL 失败，差距在**模块发现与注入时机**，不在解析算法。

### 关键函数与结论
| 函数 | 作用 | 关键指令 |
| --- | --- | --- |
| `0x1800021F0` | **模块发现循环** | 反复 `GetModuleHandleA("GameAssembly.dll")`，失败则 `Sleep(1)` 重试，直到模块出现才继续 |
| `0x180002EE0` | **API 解析** | `GetProcAddress(hModule, "il2cpp_xxx")`，结果存全局 fptr 表（0x180049xxx） |
| `0x180005490` | **主 dump 驱动** | 参数 `rcx=GameAssembly 基址`，`[base+offset]` 直接结构体访问 + 调已解析 API |
| 全局 `[0x180049BB8]` | 模块基址 | 各子函数用它把绝对指针换算成 RVA（`ptr - base`）|

### 关键证据链
1. **`GetProcAddress` 是导入的**：import table 含 KERNEL32!GetProcAddress、GetModuleHandleA/W、Sleep，无其它解析 API。
2. **导出名表是完整明文**：`.rdata` 里就是 `il2cpp_class_get_*`、`il2cpp_image_get_*`、
   `il2cpp_domain_*` 等**明文**导出名（非磁盘 VMP 加密那套），GetProcAddress 直接按名查找到目标。
3. **`0x180002EE0` 逐条解析**：`lea rdx,[il2cpp_名]; mov rcx,rbx(基址); call [GetProcAddress]; add rax,+偏移; mov [fptr],rax`
   —— 唯一解析路径，无任何"结构体直接取函数"的旁路。`+偏移` 是每条函数的全局槽上加的固定增量，非降级路径。
4. **模块发现是"等到出现"**：`0x1800021F0` 在 `GetModuleHandleA("GameAssembly.dll")` 为空时
   用 `Sleep(1)` 无限重试，直到模块在进程里被正确登记（含导出表就绪）才进入 dump。
5. **`il2cpp_handle`/`il2cpp_len`**：即模块基址 `/`模块 SizeOfImage（log 里 `0x7FFD1B460000` /
   `429387776`），由 dump 驱动 `0x180005490` 通过 `rcx` 参数接收后存到 `[0x180049BB8]`。

### 为什么自研 DLL `[FAIL] il2cpp API resolution failed`
- 自研（含 DiagProbe）在注入后**立刻**、只做**一次** `GetVolumeTypeAddress/GetProcAddress`，
  没有"等模块导出表就绪"的重试循环。
- 本机游戏注入后不久会被 NEAC 反作弊踢出（进程退出），自研若没在模块就绪的窗口期完成解析
  就是 NULL；而 299KB 版靠 `Sleep(1)` 循环把解析推迟到 `GetModuleHandleA("GameAssembly.dll")`
  非空的那一刻，配合 CE 注入时机，正好落在就绪窗口内 → 成功 dump 11525 类。

### 落地改进（自研 dumper 照抄）
1. 在解析 `il2cpp_*` 前，先加**模块发现重试循环**：
   ```c
   HMODULE hMod = nullptr;
   while (!hMod) { hMod = GetModuleHandleA("GameAssembly.dll"); if (!hMod) Sleep(1); }
   ```
2. 保证注入至少要等到游戏 **IL2CPP 运行时完成加载**（内存 ~3.5GB 以上稳态）。
3. 因 NEAC 会很快踢出注入，解析与 dump 尽量一次性快速完成，避免中途读容错重试。

## 14. 根因定性：本构建为"双重重加固"IL2CPP（2026-09-08 决定性结论）

### 两轮 DiagProbe 注入（当前 2026 构建，后续会话）给出唯一确定的判据
注入通道**完全正常**（普通体 GameAssembly.dll，GetModuleHandle 有效），GetProcAddress 探针结果：

| 分类 | 导出 | 结果 |
| --- | --- | --- |
| 核心运行时 | il2cpp_get_corlib | 0x...5F75D4B0 ✅ 解析成功 |
| 核心运行时 | il2cpp_image_get_class / _class_count / _name / _assembly | ✅ 全部成功 |
| 核心运行时 | il2cpp_init / shutdown / thread_attach | ✅ 全部成功 |
| 类型反射 | il2cpp_class_for_each | **0（NULL）** |
| 类型反射 | il2cpp_class_get_name | **0** |

### 磁盘全量明文导出名枚举（GameAssembly.dll 129240064 B）
遍历全文件 ASCII 词，得到**恰好 123 个 il2cpp_*、0 个 mono_***，全部是运行时内核类：
image（get_class/get_class_count/get_name/get_assembly）、gc、gchandle、thread、frame、
monitor、profiler、liveness2021、exception、stats、value_box、alloc/free/set_config。
**没有任何 class/field/method/domain/assembly/type 的反射 getter 明文。**

### global-metadata.dat 双份均加密
- 普通体 il2cpp_data\Metadata\global-metadata.dat 90464000 B：头 4 字节 0x57CA7923 ≠ 0xFAB11BAF，高熵。
- Super 体 il2cpp_data_super\Metadata\global-metadata.dat 79096000 B：头 0x57ED9D83 ≠ 标准魔数。
- → **离线 Il2CppDumper 直接读 metadata 同样不可行**（无解密密钥）。

### 结论：本构建对 il2cpp 运行时做了"导出裁剪 + 元数据加密"双重重加固
- 进程内存里**该导出名的确不存在**（非通道问题、非时机问题），因此**任何基于
  GetProcAddress 解析 class/field/method 反射 getter 的 dump 器在本构建上都必然失败**——
  包括自研 DLL 的 validator（要求 class_get_fields/class_get_methods ≠ NULL 永不成立）。
- 而 **299KB Unity-Offset.dll 能 dump 出 11525 类（含字段/方法）**，因为它走的是
  **运行时内存中"已解密"的 Il2Cpp 结构直接偏移游走**（§11 已确认 0x180005490 用
  [base+offset] 结构读 + 少量导出函数 image_get_class/get_corlib 引导），不依赖被裁剪的
  反射导出，也不依赖磁盘加密 metadata。

### 落地方向（立即可用）
把自研 dumper 从"GetProcAddress 反射 API"改写为 **"in-memory 结构游走"**：
1. 基础：il2cpp_get_corlib()+il2cpp_image_get_class/image_get_class_count（已确认导出），
   再按 Unity **2019.4.41f2**（VersionAboveV24=on）的 Il2CppImage/Il2CppClass/Il2CppClass 的
   vTable/metadata 结构偏移直接读取字段数组、方法数组、名字串。
2. 逐镜像补齐程序集（Image->Assembly->下一个 Image），避免依赖 domain_get_assemblies。
3. 字段/方法名经由结构里的 metadata 索引取 Il2CppMetadata 中已解密的名字串。
4. 仍走 CE 注入或自研注入都行——**通道本身已证实可用**，难点全在结构偏移。
5. 若此路再被反作弊阻挡，退路是同时对磁盘 GameAssembly.dll 做 VMP 解壳后离线
   Il2CppDumper（需先解开 global-metadata.dat 的运行时解密算法）。

  （299KB Unity-Offset.dll 用的正是 CE，可完成 11525 类+字段+方法）。
