# 2026-09-09 构建与结构游走 DLL 工作日志

## 目标

研究 `F:\gua\dump\Unity-Offset.dll` 的实现方式，并将当前项目的注入式 DLL 调整为同类效果：在目标进程内等待 `GameAssembly.dll`，从 IL2CPP 已解密运行时结构枚举镜像、类、字段、属性和方法，输出接近 `dump2026.09.03.cs` 的文本结果。

## 已确认事实

- 参考 DLL 是 x64 原生 C++ 注入 DLL，使用 `GetModuleHandleA`/`GetProcAddress`/`Sleep`，不是 Mono.Cecil C# DLL 的直接产物。
- 目标构建裁剪了 `il2cpp_class_get_fields`、`il2cpp_class_get_methods` 等反射导出，因此仅依赖反射 getter 的旧实现不能满足要求。
- 运行时实测可用的引导导出为：`il2cpp_get_corlib`、`il2cpp_image_get_class`、`il2cpp_image_get_class_count`、`il2cpp_image_get_name`。
- 已确认的 Unity 2019.4 类布局：`Il2CppClass.image=+0x00`、`name=+0x10`、`namespace=+0x18`、`fields=+0x80`；`FieldInfo.name=+0x00`、`type=+0x08`、`parent=+0x10`、`offset=+0x18`、步长 `0x20`。

## 本次修改

### `App/Il2CppRuntimeDumper/MemoryStructDumper.cpp`

- 将配置读取移到工作线程，避免在 `DllMain` 的 loader lock 中创建 C++ 容器。
- 等待 `GameAssembly.dll` 的轮询改为 1ms，最长 60 秒，行为更接近参考 DLL 的等待策略。
- 使用递归目录创建，支持配置目录不存在的情况。
- 日志增加 PID/TID、配置是否加载、GameAssembly 基址/大小/路径、关键导出地址、最终结果。
- 修正日志重复写入问题。
- 将 SEH 异常边界隔离到无对象展开的包装函数，解决 MSVC C2712，同时保留坏指针保护。

### `App/Il2CppRuntimeDumper/il2cpp_dump_core.hpp`

- 扩大结构数组候选偏移范围，支持加固构建对 `Il2CppClass` 辅助区的重排。
- 将计数字段校准范围扩大到 `0x220`。
- 限制 metadata 向前扫描到 64MiB，避免注入窗口被超长扫描耗尽。
- 增加 `ParameterInfo` 参数布局兼容：优先尝试 `type@+0x10`，兼容旧布局 `type@+0x08` 和紧凑 `Il2CppType*[]`。
- 增加校准后的布局/计数日志以及运行时参数名统计。
- 按每个镜像的 `typeStart` 重置 TypeDefIndex，避免镜像顺序造成索引串位。
- 参数读取兼容 `ParameterInfo` 的 `type@+0x10/+0x08` 与紧凑 `Il2CppType*[]` 形式。
- 配置缺失时改为 DLL 同目录的 `out` 子目录，避免落到开发机固定路径。
- 对 `MethodInfo` 尾部 token/flags/slot/参数计数增加候选布局校准和日志，减少不同 IL2CPP 版本下的方法签名错位。

### `App/Il2CppRuntimeDumper/Il2CppRuntimeDumper.vcxproj`

- 工程已切换为编译 `MemoryStructDumper.cpp + il2cpp_dump_core.hpp`，不再产出旧的反射 getter 实现。
