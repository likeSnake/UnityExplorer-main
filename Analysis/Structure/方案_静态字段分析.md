# 方案：IL2CPP 静态字段分析与 MSID 疑问解答

## 1. 问题解答 (Q&A)

### Q1: 为什么 MSID 浏览器中打印的名字很多都是 `(Unnamed)`？

**A: 这是正常的 Unity 内部表现。**

*   **机制分析**：Unity 的 `UnityEngine.Object` 基类有一个 `m_Name` 字段。
    *   对于 **GameObject**，这个字段就是你在 Hierarchy 面板看到的名字（如 "Player", "MainCamera"）。
    *   对于 **Component**（如 `Transform`, `MeshRenderer`, `BoxCollider`），它们**本身**通常不单独存储名字（`m_Name` 为空字符串）。
*   **现象解释**：
    *   我们在 Editor 的 Inspector 面板看到的 Component 名字（如 "Transform"）其实是**类型名称** (Type Name)。
    *   MSID 扫描的是内存中**所有**的 `UnityEngine.Object` 实例，不仅仅是 GameObject。
    *   所以当你看到 `Transform` 且名字是 `(Unnamed)` 时，这意味着这是一个挂载在某个 GameObject 上的组件，但组件对象本身没有被赋予独立的字符串名称。
*   **ER2 行为**：目前的 `GomManager` 或 MSID 遍历器在读取非 GameObject 对象时，尝试读取其 `m_Name`。如果为空，则显示 `(Unnamed)`。如果需要显示其所属 GameObject 的名字，需要通过 `m_GameObject` 指针反向查找，但这会增加大量内存读取开销。

### Q2: 既然是通过 MSID 读取，拿到的是 Native Object 吗？

**A: 是的，MSID 返回的是 Native Object 的地址。**

*   **内存链**：
    *   `MSID Table` -> `Native Object` (C++ 类, 例如 `Unity::GameObject` 或 `Unity::Component`)。
    *   `Native Object` -> `Managed Handle` (`GCHandle` 或直接指针) -> `Managed Object` (IL2CPP 堆上的对象頭)。
    *   `Managed Object` -> `Il2CppClass` (Klass, 类型描述)。
*   **当前代码确认**：
    *   `enumerate_objects.hpp` 中，我们首先读取的是 `Native Object`。
    *   然后通过读取 `unity_object_managed_ptr` 偏移（通常是 `0x28` 或 `0x48`），获取到 IL2CPP 层的 `Managed Object`。

### Q3: Naraka SDK 中使用的是 uint64_t，为何我们使用 uint32_t？

**A: 这是一个关于“基地址指针”通过“成员偏移量”的区别。**

通过查阅 `deps\Naraka\Offset.h`，我们发现：

1.  **基地址 / 静态地址 (uint64_t)**:
    *   例如 `inline uint64_t UnityPlayer = 0;` 或 `inline uint64_t Base_WindowBase = ...`。
    *   这些值代表的是**64位内存地址**或相对于模块基址的**大偏移** (RVA)，在64位进程中必须使用 `uint64_t`。

2.  **结构体成员偏移 (DWORD / uint32_t)**:
    *   例如 `DWORD fid = 0x340;` 或 `DWORD info = 0x10;`。
    *   这些值代表结构体**内部成员**相对于结构体起始位置的偏移量。由于结构体大小不太可能超过 4GB，标准做法是使用 `uint32_t`。
    *   `er2::Offsets` 结构体主要存储的是此类成员偏移量。

**结论**：我们将遵循此规范：
*   **偏移量配置 (Offsets Struct)**：继续使用 `uint32_t`。
*   **地址计算**：使用 `uint64_t` (或 `uintptr_t`) 进行指针运算。

## 2. 方案验证：定位 Klass 并获取静态字段

**结论：您的方案完全可行。**

这是分析 IL2CPP 游戏的标准流程。只要我们要获取的数据是 **静态字段 (Static Fields)**，我们就必须找到 `Il2CppClass`。

### 核心路径

```mermaid
graph LR
    Native[Native Object] -->|managed_ptr| Managed[Managed Object Header]
    Managed -->|klass_ptr (+0x0)| Klass[Il2CppClass]
    Klass -->|static_fields_ptr| StaticData[Static Data Region]
    Klass -->|fields_ptr| FieldsInfo[FieldInfo Array]
    
    FieldsInfo -->|Iterate| TargetField[Target FieldInfo]
    TargetField -->|offset| OffsetVal[Offset Value]
    
    StaticData -- + OffsetVal --> FinalData[静态字段值]
```

### 关键数据结构 (需补全)

目前 `er2` 库的 `Offsets` 结构体缺少 `Il2CppClass` 的完整定义。我们需要在 `offsets.hpp` 中补充以下字段：

1.  **`il2cpp_class_fields`**: 指向 `FieldInfo` 数组的指针。
2.  **`il2cpp_class_static_fields`**: 指向静态数据区域的指针。
3.  **`il2cpp_class_fields_count`**: 字段数量。

### 实现步骤

#### 第一步：扩展 Offsets 定义 (`include/er2/unity2/core/offsets.hpp`)
