# 排查方案：字段列表为空问题

## 1. 现象分析
用户反馈点击 "Inspect" 后，Field Inspector 窗口弹出但列表为空。
- **推论 1**: `Native Object` -> `Managed Object` -> `Il2CppClass` 的指针链条是通的（否则 UI 头部不会显示地址）。
- **推论 2**: 问题出在 `Il2CppClass` 内部结构的解析上，具体为 **字段数量 (Field Count)** 或 **字段数组指针 (Fields Ptr)** 的偏移量与目标游戏版本不一致。

当前使用的默认偏移：
- `fields_ptr`: `0x80`
- `static_fields_ptr`: `0xB8`
- `field_count`: `0x114` (uint16_t)

## 2. 解决方案：集成运行时诊断工具

我们不应盲目猜测偏移量，而是应在 UI 中直接显示当前的内存状态，以便精确校准。

### 步骤 1：增强 Field Inspector UI
在 `DrawFieldInspector` 函数中添加 "Debug Info" 折叠栏，显示以下原始数据：

1.  **Raw Values Check**:
    *   读取并显示 `Klass + 0x80` (预期是 Fields Ptr)
    *   读取并显示 `Klass + 0xB8` (预期是 Static Data Ptr)
    *   读取并显示 `Klass + 0x110 ~ 0x120` 范围内的 16位/32位 整数 (寻找真正的 Field Count)

2.  **Hex Dump**:
    *   添加 "Dump Klass Memory to Log" 按钮。
    *   点击后，读取 `Klass` 开始的 256 字节，以 Hex 格式 (每行 16 字节) 打印到 Log 面板。
    *   **作用**: 直接观察内存布局，肉眼定位 `FieldCount`（通常是一个比较小的整数）和指针位置。

### 步骤 2：自动试探 (Heuristics)
在代码中添加简单的试探逻辑：
- 如果 `0x114` 读出的值为 0，尝试读取 `0x118`, `0x11C` 等常见位置，并在 UI 上提示 "Suggested Count"。

## 4. 技术背景参考 (Naraka)
Narka 使用的 Unity 版本较新 (可能为 2020.3 或 2021+)，IL2CPP 结构相比旧版本有变动。
- 在部分新版本中，`field_count` 可能移动到了 `0x11C`。
- `static_fields` 可能移动到了 `0xB8` 之外的位置。

通过 Dump 内存，我们可以一目了然地看到这些变化。
